Designing repeatable Ansible automation

A reliable playbook should express desired state and avoid unnecessary changes on repeat execution.

01 / Practice

Use declarative modules

Prefer purpose-built modules to shell commands when they meet the requirement. State the expected outcome rather than prescribing every procedural step.

02 / Practice

Test and review

Use syntax checking and check mode as preliminary checks, understanding that module support varies. Test repeat runs in disposable environments.

03 / Practice

Govern production execution

Use inventories, scoped credentials, reviewed changes, execution environments and approvals. Capture evidence and define recovery steps.

Practical example

Lab and review reference

# Example playbook for an authorized RHEL lab
- name: Ensure lab package is present
  hosts: lab
  become: true
  tasks:
    - name: Install httpd
      ansible.builtin.package:
        name: httpd
        state: present

# Validation commands (run separately)
# ansible-playbook -i inventory lab.yml --syntax-check
# ansible-playbook -i inventory lab.yml --check

The playbook would install a package if executed normally. Use only a disposable or approved lab, and review package-manager and check-mode behavior.
