Kubernetes / Engineering guide

A systematic Kubernetes workload troubleshooting guide

Start with observed symptoms and narrow the failure domain before changing the workload.

01 / Practice

Inspect scheduling

Pending pods can indicate insufficient resources, taints, affinity constraints or unbound volumes. Read scheduler events first.

02 / Practice

Inspect startup and readiness

Check container status, previous logs and probe failures. A running container is not necessarily ready to serve traffic.

03 / Practice

Trace service connectivity

Compare selectors, EndpointSlices, service ports and network policies. Confirm DNS and ingress separately rather than assuming the application is at fault.

Practical example

Lab and review reference

kubectl -n demo get pods -o wide
kubectl -n demo describe pod example-pod
kubectl -n demo logs example-pod --previous
kubectl -n demo get events --sort-by=.metadata.creationTimestamp
kubectl -n demo get svc,endpointslices

Replace demo and example-pod with authorized lab resources. Previous logs exist only when a prior container instance is available.
