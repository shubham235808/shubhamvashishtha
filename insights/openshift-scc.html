Understanding OpenShift Security Context Constraints

Security Context Constraints (SCCs) govern which security-related pod settings are permitted in OpenShift.

01 / Practice

Understand admission

SCC selection depends on authorized constraints, pod requirements and admission behavior. Kubernetes Pod Security Admission is a separate mechanism; do not treat it as a direct SCC replacement.

02 / Practice

Diagnose before granting access

Inspect pod or ReplicaSet events for admission errors. Review service account privileges, image UID expectations and volume permissions.

03 / Practice

Prefer least privilege

Adapt images for non-root execution and writable paths. Do not grant broad privileged or anyuid SCC access merely to bypass an error. Review any exception with the security owner.

Practical example

Lab and review reference

oc get scc
oc -n demo get events --sort-by=.metadata.creationTimestamp
oc -n demo get pod example-pod -o jsonpath='{.metadata.annotations.openshift\\.io/scc}'
oc auth can-i use scc/restricted-v2 --as=system:serviceaccount:demo:default

Examples assume an authorized OpenShift lab; impersonation checks require appropriate privileges. SCC availability varies by release and configuration.
