GitOps / Engineering guide

Multicluster GitOps governance patterns

Separate cluster lifecycle, shared platform configuration and application delivery to make ownership and blast radius explicit.

01 / Practice

Define repository boundaries

Separate bootstrap and platform configuration from application releases. Assign owners and review requirements for shared policy.

02 / Practice

Constrain destinations

Restrict projects to approved source repositories, destination clusters and namespaces. Avoid broad administrative privileges in application controllers.

03 / Practice

Control reconciliation

Review diffs, health signals, pruning settings and resource ownership before enabling automation. Preserve data-bearing resources according to their recovery requirements.

Practical example

Lab and review reference

# Read-only Argo CD resource inventory
kubectl api-resources --api-group=argoproj.io
kubectl get applications.argoproj.io -A
kubectl get appprojects.argoproj.io -A
kubectl get applicationsets.argoproj.io -A

These examples assume the corresponding CRDs are installed and the caller has permission. Use the management cluster context appropriate to your deployment.
